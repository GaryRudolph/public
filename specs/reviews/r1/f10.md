Finding: r1.f10
Claim: fixed
Change: `session-doctor.py` runs a repo's doctor only on a runner: `CLAUDE_CODE_REMOTE=true` (Claude Code cloud, `CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE=cloud_default`, and self-hosted, `self_hosted`), `CI=true` or `GITHUB_ACTIONS=true`. Anywhere else, a workstation included, it runs nothing and prints one line telling the agent to run each doctor itself, so the run goes through Claude Code's folder trust and permissions. It no longer reads the tool's home file: the `# >>> personal >>>` block is absent on a workstation in plugin mode (`CLAUDE_MODE=plugin`, the default), so it can't tell the two apart. The docstring, core.md "Read the doctor before trusting a build" (and the regenerated Cursor rule) and makefile.md "Common tooling" name the variables.
Evidence: `plugins/personal/tests/test-session-doctor.sh`, "runner or workstation": with no runner variable, with the personal block in the home file or without it, the doctor runs nothing and prints exactly one line naming the command and repo (silent when nothing has a doctor or `PERSONAL_DOCTOR=0`); each of `CLAUDE_CODE_REMOTE=true`, `CI=true` and `GITHUB_ACTIONS=true` runs it, as does a self-hosted or cloud `CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE`; `false`, `1`, an empty value, or `CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE` alone does not; Gemini carries the line in `additionalContext`. Every case starts from `env -i`, so the machine running the tests can't leak a runner variable in.
