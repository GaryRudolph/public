Change: under GitHub Actions (`GITHUB_ACTIONS=true`), `personal-secrets/templates/secrets-repo/dist-decrypt-env.sh` and `templates/single-repo/scripts/secrets.sh` (`env`) print `::add-mask::` on stderr for every value before printing it: the value as printed, each line of a `\n`-escaped multi-line value, and the unquoted form, with `%` and CR percent-encoded so the runner registers the real string. Stderr, not the register's stdout, because callers capture or redirect stdout, and the runner parses workflow commands from both streams; the masks start on a fresh line, and every snippet that decrypts starts its step with `exec 2>&1` so masks and output reach the runner in order. The consumer template, `standards/secrets/README.md`, `makefile.md`, `estate.md`, `single-repo.md` and `personal-secrets/SKILL.md` drop every `>> "$GITHUB_ENV"` export of a value for decrypting in the step that needs it (inline for one command, a step-local `export` for several), and the standard says a repo on the old template rotates every value it exported. `make -s deploy-env ... >> "$GITHUB_ENV"` stays: it loads the committed, non-secret `deploy/<env>.env`.
Evidence: `tests/test-kit.sh` and `tests/test-single-repo.sh` gain "masking under Actions" sections (stdout unchanged, mask on stderr ahead of the value, every value of an export-all masked, multi-line and `%0A` values, no masks off Actions); against the old scripts they fail 6 and 4 checks. `grep -rn GITHUB_ENV plugins` finds only `deploy-env` and the warnings. The runner's handling of the mask is GitHub's documented behavior, not reproduced on a runner here.
