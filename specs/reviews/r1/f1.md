Change: `render_target_schema` in `agents/lib/allowlists.sh` no longer writes shell entries bare into Cursor CLI's and Claude Code's `permissions` lists, where neither tool read them. Allows are exact and denies are prefixes in both tools, by the Owner's call of 2026-11-23 after the PR's `/code-review` and `/security-review` showed that prefix allows would auto-approve `git fetch --upload-pack=<cmd>`, `rg --pre <prog>`, `make test x --eval=...` and `git log --output=<path>` in Claude Code for the first time. Claude Code allows are `Bash(<entry>)`, the exact command (an entry with a `*` gets no rule); Claude Code denies are `Bash(<entry>:*)`, or `Bash(<entry>)` as written for an entry that holds a `*` (`rm -rf /*:*` is the pattern `rm -rf /* *`, which misses the entry itself). Cursor CLI allows are `Shell(<base>:<args>)`, the exact command line from the scout's `reference.md` section 3, for a multi-word entry, and no rule for a one-word entry (Cursor reads `Shell(<word>)` as any arguments) or one with `*` or `?` or a colon in its first word. Cursor CLI denies, by the Owner's call of 2026-11-22, are `Shell(<base>:<args>*)` for a multi-word entry, `Shell(<word>)` for a one-word entry, and an entry whose args already end in `*` as written (`rm -rf /*` is `Shell(rm:-rf /*)`), so `rm -rf / --no-preserve-root` is denied too; the prefix also blocks longer commands such as `rm -rf /tmp/x`, the safe direction. Each shell entry is trimmed and its whitespace runs collapsed (unless it quotes) before any target, Cursor IDE and Gemini included, renders it, so a stray space can't drop a deny or render a rule that matches nothing; an empty entry, or a Cursor CLI deny with a colon in its first word, stops the render before anything is written. Cursor IDE `terminalAllowlist`/`terminalDenylist` and Gemini are unchanged: they were prefix rules before this change and still are, so `rg --pre <prog>` or `git log --output=<path>` still runs without a prompt there; that gap predates r1.f1 and is left for a follow-up, and the file header says which form each target gets. The scout's `_unwrap_token` reads a bare entry in either file as covering nothing, and `Bash(cmd)` as covering only `cmd`, so it proposes the wrapped rule (`reference.md` section 3 says so). The header of `agents/cursor/hooks/enforce-denylist.sh` now says the denies reach Cursor CLI and Claude Code as wrapped prefix rules, and that the IDE is the only harness where they do nothing.
