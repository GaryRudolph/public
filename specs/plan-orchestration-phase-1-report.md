# Plan orchestration: phase 0 and phase 1 report

What the work that made `personal-plan-orchestrate` harness-native on Claude Code set out to prove, how it was run and tested, what held, and what was learned. Read it before changing the orchestrate kit. The design as built is [plan-orchestration.md](plan-orchestration.md); the procedure is [`SKILL.md`](../plugins/personal/skills/personal-plan-orchestrate/SKILL.md) and [`adapters/`](../plugins/personal/skills/personal-plan-orchestrate/adapters/). This report doesn't repeat them.

## 1. Purpose and scope

- **Phase 0 (the spike)** had to prove, live, the ten exit criteria of the design proposal (v6) before anything shipped: that the workflow launch loop, the gate hook, the agents and the plugin manifest fields work on the Mac CLI and on a Claude Code cloud runner, and that the tier efforts reach the API. If criteria 1-3 or 7 failed, a fallback (the Agent path, or the passive driver in cloud sessions) would ship first.
- **Phase 1 (Claude Code)** had to ship the kit in the `personal` plugin, rewrite `SKILL.md` as a harness-neutral core with a Claude Code adapter, bring the standards in line, and dogfood it on three real plans before removing the "phase 1: dogfood" mark.
- **When and where:** 2026-10-06 to 2026-10-11, on branch `feature/orchestrate-native`, cut from `main` at `bf5da80`.
- **Not done:** phase 2 (Codex), phase 3 (Cursor's gates in code), phase 4 (Grok, optional), and the Agerpoint bok port. See [plan-orchestration.md §4](plan-orchestration.md#4-later-phases).

### 2.2 Phase 0: how each criterion was tested

- **Mac CLI, driven by tmux.** Interactive `claude` sessions (not `-p`) in a fixture of two small repos with bare local origins, under a separate `CLAUDE_CONFIG_DIR`, loading the branch's plugin with `--plugin-dir`. The subagent typed with `tmux send-keys` and pasted with `tmux paste-buffer -p` (bracketed paste), then read the transcripts. Criteria 1, 3, 4, 5, 9 (Mac half).
- **Effort on the wire.** A local logging proxy behind `ANTHROPIC_BASE_URL` captured request bodies with the Team sign-in, showing `model` and `output_config.effort` per call. Criterion 10.
- **The spike plugin.** `orch-spike`, a renamed copy of the plugin generated by a script on the branch (outside `plugins/`, so `personal` on every synced surface stayed as it was), published through marketplace `orch-spike-lab` with one `git-subdir` entry pinned to `ref: feature/orchestrate-native`. The marketplace file lived in a private scratch repo, `GaryRudolph/orchestrate-spike`, because org sync reads only a repo's default branch and on github.com needs a private repo. Criteria 6 and 7.
- **Cloud sessions C1 and C2** on the scratch repo, started and answered by Gary from prompts the wave wrote, each ending with a one-block report he pasted back. The scratch repo also held the fixture plans and a condensed parent brief standing in for the not-yet-written `SKILL.md`. Criteria 2, 7, 8, 9 (runner half).

### 2.3 Phase 1: the dogfood on `lolay/ghx`

Three real plans brought `lolay/ghx` to `lolay/triage`'s shape (three operating systems, CI, a release pipeline in dry run). Each started from ghx `main` after the previous PR merged; none stacked.

- **A, `plan-ghx-baseline-heron`:** Mac CLI, gated, with a re-entry from the pasted Kickoff prompt at a `BLOCKED` gate. PR [lolay/ghx#2](https://github.com/lolay/ghx/pull/2).
- **B, `plan-ghx-platforms-lynx`:** Mac CLI, unattended, in auto mode, continued in a new session from the pasted prompt, with a `/compact` mid-run. PR [lolay/ghx#3](https://github.com/lolay/ghx/pull/3).
- **C, `plan-ghx-release-finch`:** cloud runner session started from the desktop app, unattended, through the re-synced `orch-spike`, with a `/compact` and a planned typed `gated` switch. PR [lolay/ghx#4](https://github.com/lolay/ghx/pull/4).

For A and B, the kit was frozen in a detached worktree of the branch, loaded with `--plugin-dir`, and each session took a `--settings` file with the run's allow rules and a capture hook that appended every `Bash` and `Workflow` hook input to a log. Nobody relayed during the runs: Gary drove each from a run sheet, and afterwards one fresh subagent read the transcripts, the captures and run C's own report, applied the fixes, and flipped the gate.

## 4. What works

Proven live, by surface:

**Mac CLI** (with `--plugin-dir`, CLI 2.1.29x):
- The kickoff question, cutting and pushing a task branch only after the answer, and nothing committed on `main` before it.
- Gated stops with one question and a short handoff summary; several gates folded into one question.
- A new session from the pasted Kickoff prompt: confirming unattended (the `<pasted_content>` wrapper unwrapped), or re-posting a `BLOCKED` question without taking the paste as an answer.
- Unattended runs to the PR question with checkpoints only, across `/compact`.
- Worker commits in auto mode, `check_wave.py` on real commits, an automatic `N-fix` for a failed check, and a reword fix-up.
- The gate hook denying dishonest launches, and a hook's exit 2 blocking the Workflow call.
- A plain folder of sibling repos, gated, with the plan in `.scratch/`.
- Effort on the wire per tier.

**Cloud runner** (a web session, started from the desktop app or claude.ai/code, kit through org sync):
- An org-synced plugin delivers skills, agents, the workflow and both hooks; the workflow launches by name.
- The kickoff proposes unattended from `CLAUDE_CODE_REMOTE`, and the hook process sees it.
- A session given its own `claude/…` branch fast-forwards it to the prompt's branch and continues (C2).
- Unattended runs to the PR question across `/compact`, with every wave's plan and handoff pushed before the next launch.
- The reviewer guard denies a reviewer's write, so a workflow reviewer's `agent_type` reaches the Bash hook (`orch-spike:plan-reviewer`).
- The runner's Stop hook stays silent when the tree is clean and pushed.

## 5. What was learned

Each finding names its fix. Commits are on `feature/orchestrate-native` (§8).

### 5.1 The gate hook's transcript reading

The hook decides "did Gary say this" from transcript fields no document promises. Phase 0 captured every shape per surface, and most were misread at first:
- Mac CLI prompts are `promptSource: "typed"` or `"queued"`; web prompts are `"sdk"`. All carry `turnOrigin`/`origin.kind: "human"`.
- Compaction summaries, the `[Request interrupted by user` marker, `/compact` and other slash-command records, and `turnOrigin: "sdk"` records read as human. On the runner a compaction summary caused a false "a later human turn names gated" deny (C2).
- A message typed while the parent works is a `queued_command` attachment, which the hook never read.
- The Mac CLI wraps a bracketed paste in `<pasted_content id="…">`; the web doesn't.
- A plain deny reaches the model as `PreToolUse:Workflow hook error: …` even at exit 0.

Fixed in `17c5cd2`, with a suite record for each shape; B and C each ran a `/compact` with no deny. The lesson: capture every record shape on every surface before trusting a rule built on them, and keep each as a test fixture.

### 5.2 Step IDs

`plan_state.py` took a step's ID from its bare heading, so a standard plan whose steps restart at `s1` in each milestone stopped at gate 0 ("step id s1 appears twice"). This plan has the same shape and fails the old parser too; the bug surfaced only while the ghx plans were written, before the dogfood. Fixed in `b9b8f81`: a bare `s{K}` under `m{N}` is `m{N}.s{K}`, the prefix commit subjects already carry.

### 5.3 Org sync and plugin versioning

- The manifest's `agents`, `workflows` and `hooks` fields survive org sync. A warning that `workflows` was stripped turned out to be the Claude GitHub App not set up for the scratch repo, not a validator gap.
- A `git-subdir` entry pinned with `ref` to a branch works.
- Org sync re-reads a source only when the marketplace repo itself changes; a new commit on the pinned branch isn't enough. Plugin updates also go by `version`, and `orch-spike` had none, so a re-sync served the old kit. Fixed in `00e5be6`: the builder stamps `0.1.<commit count>`, and a one-line marketplace commit in the scratch repo makes sync look again.
- The CLI refreshes its synced copy only at session start; the desktop app needs `/reload-plugins`.
- The web's Workflow tool schema lists no plugin workflows, yet a launch by name works. Detection looks for `<P>:plan-segment` in the skills list.

### 5.4 Desktop app versus CLI plugin loading

- `--plugin-dir` outranks a synced plugin of the same name (the debug log says "shadowed by local copy"). The desktop app can't take `--plugin-dir` and loads `main`'s synced `personal`, so the Mac runs used the CLI. Run A's first session was started without `--plugin-dir`, loaded `main`'s Cursor-only skill and was aborted.
- With `orch-spike` org-synced next to `--plugin-dir personal`, two gate hooks run on every Mac launch. A stale copy would deny what the new one allows, so the run sheet diffed the synced copy against the branch before each run.
- `ANTHROPIC_DEFAULT_OPUS_MODEL` and `ANTHROPIC_DEFAULT_SONNET_MODEL` didn't remap the workflow's or agents' models, so spike runs couldn't use cheap stand-ins and cost real Sonnet and Opus.
- A spike session's `/effort` saved itself to the config's `settings.json`, as did a dialog's skip flag and workspace trust. Spike sessions change the config they run under.
- The Agent tool ran probe agents in the background even when asked for foreground; the Agent path passes `run_in_background: false`.

### 5.5 Standards path precedence

Run A's session read `plan-execution.md` from the `~/Projects/personal/public` checkout before the plugin's own copy, by `core.md`'s usual order, so the frozen kit didn't pin the standards. Fixed in `60443ae`: the skill reads every standards file it cites, and points workers at, inside its own plugin.

### 5.6 Outward actions by workers and reviewers

- Phase 0: a reviewer's Bash could write; only its instructions stopped it. m2.s2 added a `PreToolUse` Bash guard keyed on `agent_type`.
- Run C: a worker ran the repo's formula publish script without its dry-run flag, inside a compound command, against the plan. Only the auto-mode permission classifier stopped it. The worker disclosed it under surprises, and the parent didn't log it.
- Fixed in `43e7362` in three layers: the worker prompt and agent files forbid outward commands, naming the repo's own publish scripts except the spec's dry-run form; workers return a required `breaches` list that the workflow surfaces to the parent and the reviewer; and the guard became `agent_guard.py`, which also denies a worker's clearly outward commands (`git push`, `gh pr` and `gh release` writes, `gh workflow run`, non-snapshot goreleaser, publishes without `--dry-run`). Replaying the 367 captured Bash calls of runs A and B gave no worker deny and unchanged reviewer decisions.
- Run C's reviewers hit the guard three times by redirecting `make ci` output to a file. The reviewer prompt and the deny text now say to read output inline.

### 5.7 Carrying decisions and environment notes

In run C each agent rediscovered the same runner toolchain workarounds, and the `[deep]` waves ran about 2x their estimate. Later groups also had no way to see decisions earlier waves made; the parent appended them to the Review log. Fixed in `43e7362`: `args.decisions` and `args.environment` ride into every worker and reviewer prompt, workers report new workarounds as `env:` lines, and the handoff keeps "Decisions so far" and "Environment notes".

### 5.8 Procedure gaps the spike and dogfood closed

- A step that changes no file needs an empty commit, or the check fails; on the runner a fix-up worker refused one and stopped an unattended run (C1).
- Rewording a commit below the parent's bookkeeping commits replays them; the parent force-pushes with a lease.
- A gate approval goes in a top-level `approval` string beside `approved: [{gate, wave}]`; nesting it was denied (C1).
- `check_wave.py` reported the parent's own bookkeeping commit as a stray in a directory with no group.
- A plain folder of sibling repos nested in another repo's work tree read as part of that repo.
- The runner's Stop hook is a git check (dirty or unpushed tree), not a timer, and the web harness blocks `sleep N; cmd` chains: the parent replies in one line and waits for the notification.
- A runner session can lack access a group needs (`gh` returned 403 on `lolay` in run C): one read-only access call before such a group.

### 5.9 Token accounting and costs

**Accounting gaps found:**
- A session that ended at a gate didn't log its own parent line; run A's log missed about $2.5. Every save that waits or ends now logs the parent's open stretch.
- A resumed session reused the `orchestrator-kickoff` label; it is now `orchestrator-resume`.
- Worker lines are `(output est.)`; the session's `cost-state` record is exact but covers several rows, so it goes in one line under the Cost table.
- The price table had no `claude-haiku-5-5` row; that line was priced at Haiku 4.5.
- The orchestrator row's estimate ran high in all three dogfood runs (0.3-0.7x).

**Why the plan cost ~$124 against ~$54:**
- **Long-lived subagents kept open across human round trips.** Wave 3's Opus worker (~$13.6) stayed alive through every C1 and C2 exchange, so each resume re-read a context past 300k tokens. Wave 7's single dogfood fix-up subagent cost ~$14.8 on its own.
- **Parent context reloads after resumes.** The orchestrator session resumed across several days; each resume rewrote its whole cache (~$3.8 on 2026-10-08, ~$8.9 over the dogfood days). The orchestrator row came to ~$32 against ~$20.
- **Spike runs.** Real sessions on real models (§5.4) cost ~$19.7 against ~$8 of allowances, mostly real Sonnet workers on the Mac and two Opus cloud parents.
- **Two attempts at wave 1** while the CLI was signed out.

The dogfood plans' own spend, ~$35 by their Token logs (~$42 by `cost-state`, which includes post-completion turns), is outside the ~$124.

**What to do differently:**
- Use short-lived subagents: one per task that finishes and returns, never one that waits across a human's replies.
- When a step needs a human to drive sessions, write a run sheet the human follows directly, and have a fresh subagent read the evidence afterwards. Don't keep a relay subagent alive.
- Continue a long plan in a new chat from its Kickoff prompt (about 30k tokens to start) rather than resuming an old session days later. `/compact` saves little for the parent.
- Budget spike runs as real-model sessions; model remaps don't make them cheap.

## 6. Defaults chosen and open to revisit

The dogfood fix-up chose five defaults Gary may want to change:

| Default | Choice | Alternative |
|---|---|---|
| Gate 5 on a single-group wave, gated | Stays a stop, folded into one question with the next unit's gates | Skip it |
| A worker's disclosed breach | CONCERNS when it was blocked (gets `N-fix`); gate 1 in both modes when it ran | Always gate 1 |
| The worker guard's scope | Narrow: only clearly outward commands; a repo's own publish scripts are left to the prompt and `breaches` | Deny by script name or path |
| Cursor sessions, cloud agents included | Propose gated, since no hook checks the answer | Propose unattended on a Cursor cloud agent once phase 3 lands |
| The guard's name | `reviewer_guard.py` renamed `agent_guard.py` | Matters for the Agerpoint port |

Gary's decisions from the design, as the kit implements them ([plan-orchestration.md §5](plan-orchestration.md#5-decisions) has the full statements):
- **2:** a planned `[xdeep]` wave is a logged checkpoint unattended; unplanned `[xdeep]` stops.
- **3:** two automatic fix-ups per group; the third failure in a row stops.
- **4:** the canary stays in both modes; unattended passes it on a clean check and review.
- **5:** one unit per run.
- **6:** task branches only, on every machine.
- **7:** one Opus reviewer per working directory per unit.
- **8:** the Agerpoint bok port follows phase 1's live runs.
- **9:** a plain yes to a kickoff question proposing unattended confirms it.
- **10:** scope breaches stop at gate 1 in both modes.
- **11:** no git remote means gated only.
- **12:** unreviewed worker commits are pushed at a stop, labeled `UNREVIEWED`.
